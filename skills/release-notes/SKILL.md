# Release notes playbook

1. Collect what changed since the last release (merged PRs, closed tickets).
   If you can't see them yourself, ask a crew member who can.
2. Group into: ✨ New, 🐛 Fixed, ⚠️ Breaking, 🧹 Internal.
3. Write one line per change, in user language ("You can now…"), not commit-speak.
4. Breaking changes get a "What you need to do" line each.
5. Hand the draft to the scribe for a polish pass, then post it.
6. Never ship release notes on a Friday afternoon. Same rule as deploys.
